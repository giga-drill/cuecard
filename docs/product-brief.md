# FloatCue iOS 悬浮提词器

## 产品目标

FloatCue 以开源项目 CueCard 的 iOS 悬浮提词器为基线，首版做一个优先悬浮在 Apple 系统相机上方的提词器。

## 已确认的新增需求

### 1. 横竖屏布局

- 默认按手机竖屏使用，悬浮提词器为竖向布局。
- 手机横过来拍横版视频时，悬浮提词器也切换为横向布局。
- 切换方向时不能丢失当前阅读位置、播放/暂停状态和计时进度。

### 2. 语音跟读滚动

- 保留按固定速度自动滚动的基础模式。
- 增加语音跟读模式：根据用户实际说到的文稿位置推进文字。
- 用户停顿时停止推进，语速变化时平滑跟随。
- 口误、重复、跳句后应尽量重新找到正确位置，不能因为一个常见词突然跳到文稿末尾。

## 已确认的首发边界

- 第一版只优先支持 Apple 系统相机，不承诺兼容抖音、小红书、微信等第三方录制 App。
- 语音识别只支持普通话中文（`zh-CN`）。
- 只使用设备端语音识别；设备或当前语言模型不支持端侧识别时，不允许联网识别，直接退回定速滚动。
- 系统相机激活后若导致麦克风中断、收不到音频或识别任务失败，立即退回定速滚动，不在后台反复争抢麦克风。
- 第一版不内置相机录制；真机验证若证明系统相机无法稳定与后台语音共存，仍保留悬浮定速模式。

## 当前工程决策

- GitHub 仓库采用标准 fork 工作流：`origin` 是 `giga-drill/cuecard`，`upstream` 是 `thisisnsh/cuecard`，只从上游拉取更新，不向上游推送。
- 第一版采用本地优先、无账号模式。移除 Firebase、Google 登录、云端统计和 Crashlytics；文稿与设置继续保存在本机。
- 画中画使用 iOS 公开 API。App 不再通过非公开调用强制进入后台，用户启动画中画后自行切换到相机或录制 App。

## 本轮边界

本轮已完成：

- 横竖屏 PiP 尺寸跟随，方向变化不重置阅读位置和播放状态；
- 固定 `zh-CN`、强制端侧的 Apple Speech 流式识别；
- `playAndRecord + mixWithOthers` 音频会话、buffer 心跳和结构化诊断；
- 权限、端侧模型、音频中断、无 buffer 或识别错误后的定速降级；
- 中文局部模糊对齐、停顿、重复、口误和跳句处理；
- 主界面与 PiP 的语音平滑滚动；
- 29 项单元测试、iPhone 17 / iOS 26.5 模拟器构建和 arm64 真机 Debug 编译。

尚未完成：真实 iPhone 上与 Apple 系统相机的麦克风共存测试和 App Store 发布。真机测试完成前不得宣称系统相机语音跟读已经兼容。
